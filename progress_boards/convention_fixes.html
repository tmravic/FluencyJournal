Convention fixes

Ordered from the smallest edit to the change that touches the most behavior. Each item says where it lives, what convention it breaks, and the shape of the fix. Sass and BEM sit in this same list. Gem replacements are at the end.

Medium

Medium44. Load a nested record through its parent

app/controllers/entries_controller.rb set_entry, entry_params. app/controllers/ai_queries_controller.rb set_ai_query. app/controllers/quiz_answers_controller.rb set_quiz_answer, show, create.

The journal in the URL is current_group.journals.find, and the quiz is @journal.quizzes.find. The child is still a global find: Entry.find, AiQuery.find, QuizAnswer.find, and AiOutput.find for the posted output id. Show, edit, update, destroy, speak, and cancel can act on another group’s row. entry_params also permits :journal_id, so create and update can move the entry onto a journal that is not the one in the URL.

Use @journal.entries.find, @journal.ai_queries.find, @quiz.quiz_answers.find, and @quiz.ai_query.ai_outputs.find. Drop :journal_id from entry_params. Quiz peek and hint already load the output through the quiz.

Hard

Hard45. Load a followup through an owner this user can touch

app/controllers/followups_controller.rb set_followup, new, create, destroy. app/controllers/ai_outputs_controller.rb set_ai_output. app/controllers/notes_controller.rb new_automatic, create.

Followup.find and AiOutput.find are global, so show, destroy, and speak accept any id. new allowlists the origin class and then calls klass.find. create constantizes followup_origin_class with no allowlist and finds that id. The journal-followup branch is the exception: it uses current_group.journals.find. Destroy also loads Journal.find from params[:journal] for the redirect. Automatic notes load AiOutput and AiQuery by id, and create then sets made_note on that output. A note-followup query often has a null journal_id, so scoping only through current_group.journals misses it.

Resolve each id through an owner this request may use. Journal-backed entries, queries, and outputs come from current_group. A note origin comes from Current.user.notes. A followup is visible only when its origin is one of those. Use the same allowlist in create that new already has. 404 otherwise.

Hard46. Keep one query and one followup on a prompt

app/models/prompt.rb, db/schema.rb, app/jobs/prepare_quiz_job.rb, app/jobs/grade_quiz_job.rb, app/jobs/application_job.rb

Prompt declares has_one :ai_query and has_one :followup, both dependent: :destroy. The indexes on ai_queries.prompt_id and followups.prompt_id are not unique. has_one destroys only the loaded row. A second child leaves prompt_id set, and deleting the prompt raises a foreign-key error. PrepareQuizJob saves the query before the transaction that creates the quiz and hints. ApplicationJob retries ActiveRecord::Deadlocked. A retry after that commit inserts another query for the same prompt. GradeQuizJob has the same shape: the query is saved, then later work can raise and the job can run again.

Add a unique index on each prompt_id. Create the prepare query inside the same transaction as the quiz. Item 35 assumed one child per prompt. The schema still allows more.
