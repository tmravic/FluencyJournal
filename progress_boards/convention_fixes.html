Hard36. Stop grading from stealing ai_query_id

app/jobs/grade_quiz_job.rb, app/models/ai_query.rb, app/models/quiz.rb, app/controllers/quizzes_controller.rb show

quiz.update(grading_ai_query_id: ai_query_id) is the right write. The next line, quiz.grading_ai_query.quizzes.push(quiz), uses has_many :quizzes, and that association always sets ai_query_id. The push saves the quiz again with the grading query as its owner, so the quiz leaves the query that holds the questions. dependent: :destroy on AiQuery#quizzes then ties the quiz’s lifetime to the grading query. QuizzesController#show reads @quiz.ai_query for the per-entry feedback, so the show page currently depends on this overwrite.

Add has_many :graded_quizzes, class_name: "Quiz", foreign_key: :grading_ai_query_id. Delete the push. Teach show to read the question query and the grading query as two associations. This is the hardest item because the show page, destroy callbacks, and the job all assume the overwritten id.
