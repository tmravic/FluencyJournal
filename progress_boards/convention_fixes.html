Convention fixes

Ordered from the smallest edit to the change that touches the most behavior. Each item says where it lives, what convention it breaks, and the shape of the fix. Sass and BEM sit in this same list. Gem replacements are at the end.

Easy

Easy8. Format dates with the locale

app/helpers/application_helper.rb display_next_review_time, and the same strftime("%m/%d/%Y") in app/views/journals/_journal_content.html.erb and app/views/entries/_entry.html.erb

The app has English and Japanese locales. strftime ignores both, and comparing formatted strings to decide “today” is a second clock. Rails already has l / I18n.l and to_date.

Compare dates, then format the one you show with l(date).

Easy9. Use Time.current for due dates

app/models/journal.rb, app/models/note.rb, app/controllers/journals_controller.rb, app/controllers/notes_controller.rb

next_to_study compares with DateTime.now. finished_today uses 24.hours.ago, which follows Time.zone. Creates also assign next_study_date = DateTime.now in the controller, even though the model requires the column and the column has no default. config.time_zone does not affect DateTime.now. On a UTC server those two clocks disagree by the offset of Asia/Tokyo.

Use Time.current, write the scope as where(next_study_date: ..Time.current), and set the initial date in the model with attribute or before_validation.

Easy10. Fix the spacing token used as a font size

app/assets/stylesheets/layouts/_header.scss

Inside the small-phone mixin, h1 gets font-size: var(--space-l) and h3 gets var(--space-m). Those custom properties are spacing steps, not type steps. The type scale is already --font-size-*.

Use a font-size token. Same file family: config/_variables.scss comments both --space-xxxxs (0.125rem) and --space-xxxs (0.25rem) as “4px”. Only the second one is 4px.

Easy11. Use the breakpoint mixin you already wrote

app/assets/stylesheets/components/_note.scss, app/assets/stylesheets/mixins/_media.scss

Dart Sass setup is in good shape: partials use @use, and components/_index.scss @forwards the media mixin. One block ignores that and writes @media (max-width: 50rem) by hand. tabletAndUp is min-width: 50rem, so this raw query is the other side of the same breakpoint, spelled a second time.

Add a tabletAndDown arm to the mixin, or call the mixin. A later cleanup can store the widths in a sass:map so the numbers live in one place. Do not go back to @import.

Medium

Medium12. Pass "all" from the All Journals page

app/views/journals/all.html.erb

The start button and the empty state get from_all_or_todays: 'todays'. The controller sets @from_all_or_todays = "all", and the turbo-stream template uses that variable. A full page load of All Journals then creates a journal as if you were on today’s list, so the close button returns to journals_path instead of all_journals_path.

Pass @from_all_or_todays. all_or_todays in app/helpers/journals_helper.rb has a related guess: it returns "todays" only when @todays_journals is present. Broadcasts and the mark-studied re-render never set that variable, so edit and delete links get stamped "all".

Medium13. Stop passing locals: into a turbo frame tag

app/views/notes/index.html.erb, all.html.erb, drafts.html.erb

locals: is an option for render, not for turbo_frame_tag. Rails prints it as an HTML attribute. The frame id still works, so this is noise, not a crash.

Delete the option.

Medium14. Open a journal from a note in the top window

app/views/notes/_previous_followups_on_note.html.erb, app/views/journals/show.html.erb

The journal chip sets data-turbo-frame="notes_box". Turbo then looks for notes_box in the response. The journal page’s copy of that frame is empty, so the notes panel is replaced by nothing and the journal never opens.

Use data: { turbo_frame: "_top" } if the journal should take the whole page, or target workspace if it should open beside the notes.

Medium15. Close notes should close the panel

app/views/notes/_close_notes_button.html.erb, app/views/journals/index.html.erb

The close control targets #notes_box at journals_path. On the journals index that frame is empty and has src: notes_path, so Turbo loads today’s notes again.

Point the close action at a response whose notes_box frame is empty and has no src.

Medium16. Make prepare, grade, and reset real writes

config/routes.rb, app/controllers/quizzes_controller.rb, app/views/quizzes/_quiz_buttons.html.erb, _grade_quiz_button.html.erb, _reset_quiz_button.html.erb

prepare_quiz saves a prompt and enqueues PrepareQuizJob. grade_quiz does the same for grading. reset_quiz calls destroy_all_unfinished_quizzes!, which destroys every unfinished quiz on the journal, not one quiz. All three are get routes hit by link_to. GET is allowed to be prefetched, cached, and retried. It also carries no CSRF token, so another site can start a paid xAI call or delete in-progress quizzes.

Use button_to with POST for prepare and grade, and DELETE for reset. Keep the turbo-stream response. Rename reset so the label matches “every unfinished quiz on this journal,” or scope the destroy to the one quiz on the page.

Medium17. Do not create a row inside new

app/controllers/followups_controller.rb

For JournalFollowup, new calls find_or_create_by!, then calls it again if the origin is still nil. Note followups also write session[:followup_from_todays_notes]. The Double Check button is a normal link. The first prefetch creates a JournalFollowup. params[:id] on this action is the origin id, not a followup id.

Build the followup in memory. Create the origin in create, which is already POST.

Medium18. Leave a studied note or journal off today’s list

app/views/journals/mark_journal_as_studied.turbo_stream.erb, app/views/notes/mark_note_as_studied.turbo_stream.erb

Both templates remove the record, then render that same record again with turbo_stream.after or prepend. That is the create-stream pattern. After “studied,” next_study_date is in the future, so the row should stay off today’s list. If nothing else is due, the journal stream also replaces the whole journals frame with the today’s empty state, even when that frame is All Journals. Both templates also query Current.user from the view.

Remove the row and update the count. Do not insert it again. Pass the empty-list decision in from the controller.

Medium19. Do not nest a frame inside the same id

app/views/journals/reading_mode.turbo_stream.erb, app/views/entries/_entries_frame.html.erb, app/views/quizzes/peek.turbo_stream.erb, app/views/notes/_note_display.html.erb with _change_note_due_date_button.html.erb

A turbo-stream update replaces the inside of a frame. These templates put a partial back in that is itself turbo_frame_tag with the same id. Reading mode does it to #entries. Peek and unpeek do it to the quiz-entry frame. The note due-date button is wrapped in change_note_due_date_#{id}, and the partial renders that id again. getElementById then hits whichever copy comes first.

The partial that fills a frame should be the inner HTML only. One owner renders the turbo_frame_tag.

Medium20. Delete the quiz, and restore the journal around it

app/views/quizzes/show.html.erb, app/views/quizzes/_graded_output.html.erb, app/views/ai_queries/destroy.turbo_stream.erb

The button says delete the quiz. The path is journal_ai_query_path. AiQuery has has_many :quizzes, dependent: :destroy, so the quiz, its outputs, and its hints go with the query. The destroy stream clears the assistant and does not put entries and journal buttons back. close_quiz.turbo_stream.erb already knows how to do that. AiQueriesController#destroy also has an empty format.html and no template, so a non-Turbo DELETE has nowhere to go. Followup destroy and destroy_selected have the same missing 303.

Add quizzes#destroy and a 303 back to the journal. Reuse the close-quiz stream for the Turbo case.

Medium21. Delete a prompt template by id, for this user

app/controllers/followup_template_prompts_controller.rb, app/controllers/concerns/template_prompt_concern.rb

DELETE is the right verb. The body is the template text, and find_by(base_content:) has no user_id. base_content is not unique, so the row that comes back can belong to someone else. The route never names a record.

Submit the id. Scope the destroy with by_user(Current.user).

Medium22. Give each quiz UI action one member id

config/routes.rb peek, unpeek, hint, and original-language routes; app/controllers/quizzes_controller.rb

These GETs do not write, so the verb is fine. They are collection routes that load one quiz from the query string, and each action uses a different parameter name: quiz_id, ai_output, quiz, quiz_entry. unpeek does AiOutput.find(params[:frame].split("_").last) on a DOM id. The path never contains the quiz id.

Make them member routes. Pass the output id as a parameter, not as a piece of a frame id.

Medium23. Followup create should redirect to the row it saved

app/controllers/followups_controller.rb create

The saved record is @followup_prompt.followup. The HTML branch redirects to followup_path(@followup), and create never assigns @followup. Turbo hides this because it does not use that redirect.

Redirect to the followup that was just saved, with status 303.

Medium24. Put previous_journal on the list the page is showing

app/models/journal.rb, app/models/note.rb

Both methods call Current.user&.journals.order (notes do the same). If Current.user is nil, &. does not cover .order, so this raises. The journal page lists current_group.journals, not Current.user.journals, so the Turbo insert can land after a row that is not on the page. The Arel lt is a range query written by hand.

Pass in the relation, and write where(next_study_date: ...next_study_date).order(:next_study_date).last.

Medium25. Flatten button modifiers

app/assets/stylesheets/components/_btn.scss

BEM modifiers sit beside the block: .btn--primary and .btn--short together on one element. Nesting &--short inside &--primary compiles to .btn--primary--short, a modifier of a modifier. The views then have to repeat that chain (btn btn--primary btn--primary--short). .btn--journal-short is the same idea with a hyphen that does not match the element separator.

One class per modifier, both on the element: btn btn--primary btn--short. Put &--short next to &--primary, not inside it.

Medium26. An element does not contain another element

app/assets/stylesheets/components/_form.scss, app/assets/stylesheets/components/_card.scss

&__button_block inside &__input compiles to .form__input__button_block. .card__change__title and .card__change__corrected are the same shape. BEM allows block__element only one level deep. A second __ means the element has been treated as a block without being named as one.

Use .form__actions and .card__title, or start a new block (.change) if “change” has its own elements. .card__change_content should be .card__change-content so the separator is a hyphen, not a second underscore.

Medium27. One naming scheme, and no id selectors

app/assets/stylesheets/components/_note.scss, _quiz.scss, _quiz_answer.scss, _request_form.scss, _navbar.scss, _followup.scss

Blocks and elements are mixed three ways. .empty-state and .visually-hidden use hyphens. .note__change_due_date, .notes_box_scroll, .quiz_delete_buttons, .quiz_answer, .request_form, and .send_button_box use underscores as if they were elements of a block that was never named. .note__link-journals-label then switches back to hyphens. #send_button styles an id. BEM does not style ids, because an id cannot be reused and it overrides every class.

.header is also a layout block in layouts/_header.scss and a nested class inside .note__header. Those are two components sharing a name, so a header rule in one file changes the other.

Pick hyphens for multi-word blocks and elements (.notes-box, .note__due-date, .quiz__delete). Rename .header inside a note to .note__toolbar. Replace #send_button with .request-form__submit.

Medium28. Keep each block’s rules in its own file

app/assets/stylesheets/components/_note.scss, _entry.scss, _followup.scss

Dark-theme .btn--journal-short lives in the note file. .note .form__group, .note .form__input__button_block, and .form.entry textarea.form__input reach into the form block from outside it. .followup .form__checkbox-label does the same. A block owns its elements. Another block may sit next to it; it should not retune its insides.

Move the dark button rule into _btn.scss under [data-theme="dark"]. If a form inside a note needs a different layout, add a form modifier such as .form--stacked and put that rule in _form.scss.

Medium29. Replace the one-off inline styles

app/views/journals/_journal_content.html.erb, reading_mode.html.erb, compare.html.erb, app/views/pages/home.html.erb, scaffold style="color: green" notices on entry and note show pages

These repeat the same margin and flex rules the spacing tokens and .flash already express. Inline style skips the dark theme and the type scale.

Use .journal__date--split (it already exists), a small .stack utility or a block modifier for the vertical rhythm, and the flash partial for notices.

Hard

Hard30. Let followup and quiz jobs fail in the open

app/jobs/followup_request_job.rb, app/jobs/application_job.rb, app/jobs/prepare_quiz_job.rb, grade_quiz_job.rb, prepare_quiz_hint_job.rb, app/services/x_ai_service.rb

FollowupRequestJob rescues StandardError, logs it, and returns. ActiveJob then marks the job successful, so there is no retry and no Turbo update. The page stays on “processing.” ApplicationJob only retries deadlocks.

The three quiz jobs copy the Faraday call, slice token counts by hand, and JSON.parse the body without checking status. A 429 or 500 becomes NoMethodError or JSON::ParserError. XAiService already raises ApiError unless the response succeeded, and it already reads usage. AiRequestJob uses that service, but ApiError is still not in retry_on.

Call XAiService from the quiz jobs. Add retry_on for ApiError and Faraday timeouts. On the final failure, broadcast an error into the same frame the success path uses. Delete the rescue StandardError that swallows the job.

Hard31. Take the repair job out of the parser

app/models/ai_query.rb parsed_response, app/jobs/rescue_bad_format_job.rb

A reader calls RescueBadFormatJob.perform_now when JSON is invalid. That is a synchronous xAI call from a parse, including from count_changes before the query has a prompt. The job updates raw_response, rescues JSON::ParserError and a bare rescue, and still returns the string. Callers then see nil or a second parse error, and the job has no failed state.

change_content in the same model returns nil as soon as the backup key is missing, so the later error branch never runs. AiOutput#assemble_ai_output_content then calls .first on that nil.

Parse in the job that received the HTTP body. If the body is bad, retry or discard there. A model method should return data or raise, not start work.

Hard32. Use one entry order

app/models/journal.rb full_journal, app/models/entry.rb entry_number, app/models/ai_query.rb hint creation, app/helpers/quiz_answer_helper.rb

full_journal orders entries by id. Hint creation uses journal.entries[index] with no ORDER BY. PostgreSQL does not promise that matches id order. entry_number orders by created_at and loads every entry once per row. The quiz helper runs offset per form. Quiz#full_journal is a third meaning: it plucks quiz_answers.user_response, while Journal#full_journal plucks entry text. AiOutput#identifier is also three kinds of value in one string: "1", "corrected_text", or "assessment".

Pick entries.order(:id) and use it in the hint job, the helper, and entry_number. Rename Quiz#full_journal to something like responses. Split identifier into an enum, or at least stop overloading one column for a line number and a role. NotesFollowup expects a table named notes_followups; the HABTM table is followups_notes. Nothing in the app uses that model. Delete it or point it at the real table.

Hard33. Make Prompt subclasses substitutable

app/models/prompt.rb and the subclasses under app/models/, app/services/x_ai_service.rb

Single-table inheritance only pays off when every subclass answers the same messages. Here role_prompt and response_format take (user), (user, journal), (journal), or (journal, quiz, user) depending on the class. XAiService always calls role_prompt(user, journal) and response_format(user). base_content means journal text, a followup question, or reference text. Prompt#original_language returns that column, not a language name, and it collides with the same method on User. abbr is copied on Prompt and AiQuery, and an unknown language falls back to the word "English" rather than "en". TTS uses "ja"; the models use "jp".

Give every prompt the same two methods with the same arguments. Keep language names on User. One abbreviation map should feed both the chat client and TTS.

Hard34. Store a followup link once

app/models/followup.rb, app/models/entry.rb, note.rb, ai_output.rb, ai_query.rb

Followup already belongs_to :origin, polymorphic: true. Entry, Note, AiOutput, and AiQuery also keep a HABTM to followups, and the service pushes the followup onto both. origin_followups is a third name for the polymorphic side. HABTM cannot dependent: :destroy the other side, which is why before_destroy walks the joins by hand. dependent: :nullify clears origin_id and leaves the join rows.

Keep the polymorphic has_many :followups, as: :origin. Drop the HABTM joins once every screen reads origin.

Hard35. Break the followup destroy cycle

app/models/followup.rb, app/models/ai_query.rb, app/models/prompt.rb, app/controllers/followups_controller.rb

Followup’s before_destroy destroys each linked AiQuery and its outputs. AiQuery’s after_destroy calls prompt.destroy!. Prompt has both has_one :ai_query, dependent: :destroy and has_one :followup, dependent: :destroy, so destroying the prompt tries to destroy the followup that is already inside before_destroy. followups.prompt_id is also a foreign key, so the prompt row cannot go first. The controller calls destroy and ignores a false return. The Turbo stream can remove the followup from the page while the database rolls the delete back.

Pick one owner. Outputs already use dependent: :destroy on the query. Destroy the followup, then the prompt, in an order the foreign key allows. Delete the before_destroy / after_destroy pair that re-enters the same records. Check the return value before rendering the stream that removes the node.

Hard36. Stop grading from stealing ai_query_id

app/jobs/grade_quiz_job.rb, app/models/ai_query.rb, app/models/quiz.rb, app/controllers/quizzes_controller.rb show

quiz.update(grading_ai_query_id: ai_query_id) is the right write. The next line, quiz.grading_ai_query.quizzes.push(quiz), uses has_many :quizzes, and that association always sets ai_query_id. The push saves the quiz again with the grading query as its owner, so the quiz leaves the query that holds the questions. dependent: :destroy on AiQuery#quizzes then ties the quiz’s lifetime to the grading query. QuizzesController#show reads @quiz.ai_query for the per-entry feedback, so the show page currently depends on this overwrite.

Add has_many :graded_quizzes, class_name: "Quiz", foreign_key: :grading_ai_query_id. Delete the push. Teach show to read the question query and the grading query as two associations. This is the hardest item because the show page, destroy callbacks, and the job all assume the overwritten id.

Gems that replace hand-rolled pieces

These are libraries for work this app already does itself. None of them fix the HTTP or association bugs above. They shrink the code those bugs live in.

ruby_llm

app/services/x_ai_service.rb, the Faraday copies in the three quiz jobs, and app/jobs/rescue_bad_format_job.rb

ruby_llm speaks xAI along with the other chat providers. It handles the HTTP call, the error status, and token usage, and it can ask for structured output so the response is a Ruby object instead of a string you parse and repair. That covers XAiService, the duplicated quiz-job clients, the fence-stripping in parsed_response, and most of RescueBadFormatJob.

If you would rather keep the current request shape, ruby-openai pointed at https://api.x.ai/v1 is the smaller swap for XAiService alone. Pair it with faraday-retry so timeouts and 429s retry in Faraday instead of disappearing inside rescue StandardError.

local_time

app/helpers/application_helper.rb display_next_review_time, and the strftime calls in the journal and entry views

local_time renders a <time> tag and formats it in the browser’s zone. That replaces the hand-rolled “today” string compare and the US-only month/day/year format, and it follows the person looking at the page rather than the server’s DateTime.now.

supermemo

app/controllers/journals_controller.rb mark_journal_as_studied, and the same interval step on notes

Studied items schedule themselves with last_interval * 2.5. That is a short version of SM-2, with the ease factor and the lapse rules left out. supermemo is that algorithm. The model would store the interval and the ease the gem returns, instead of the controller inventing the next date.

acts_as_list

app/models/journal.rb full_journal, app/models/entry.rb entry_number, hint creation in app/models/ai_query.rb

Line numbers are three different orders: id, created_at, and whatever PostgreSQL returns with no ORDER BY. acts_as_list puts a position on entries and gives you order(:position) as the only order. Quiz lines, hints, and entry_number then share one sequence. This is worth it only if entries can be reordered. If they are append-only, item 32 (always order(:id)) is enough and you do not need the gem.

view_component

The journal action row, quiz buttons, and note header are large partials that take a shifting set of locals (journal, from_all_or_todays, source_tag). Several of the Turbo bugs above are a partial rendered into the wrong frame, or locals: passed to the wrong helper.

ViewComponent turns one partial into an object with an explicit initializer and a test. It does not pick HTTP verbs for you. It does stop the “which local did this partial expect?” class of bug, which this app hits often. Adopt it for new buttons and frames first. A wholesale rewrite of app/views is a separate project.
